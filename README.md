# Safar · سفر

A cross-platform app for **Pakistan Railways**: iOS, Android and web from one
codebase. Find a train, book a berth, get to the platform, watch the train move,
and know how to get onward at the other end.

Built with Expo (React Native 0.76, Expo Router 4) in TypeScript, with a Node
gateway that reads from the operator's existing reservation and control systems
and keeps the Google Maps billing key off the phone.

```
npm install
npm start          # then press i, a, or w
```

The app runs immediately with no backend and no API keys. The bundled timetable
is the real one. Green Line, Tezgam, Khyber Mail, Jaffar Express and nine
others, with their real numbers, calling patterns and journey times.

## The design

The structure is Airbnb's, deliberately and in detail, because their system is a
solved problem for photo-led marketplace UI and re-deriving it would only make
it worse:

| | |
|---|---|
| **One chromatic accent** | Everything colourful descends from `#01411C`, the green of the flag, lifted to `#0E7A3A` where it has to clear 4.5:1 on white. Neutrals are Airbnb's own greys. |
| **Type** | Manrope, the closest freely-licensed face to Airbnb Cereal: geometric skeleton, humanist detailing, tall x-height. One family, six weights, no serif anywhere. |
| **4px grid, soft corners** | 8 on buttons, 12 on cards and images, 24 on sheets, pill on search. |
| **Photography does the talking** | 34 real photographs of Pakistani stations, trains and cities, harvested from Wikimedia Commons with their licences and photographers recorded. Nothing is stock and nothing is generated. |
| **Drawn, not imported** | The icon set (60 glyphs), the logo, and the app icons are all drawn in code on a 24-unit grid. No icon font, no exported PNG blobs. |
| **Motion explains** | One spring config in the theme drives every press. The wishlist heart overshoots and settles; the train marker glides between position updates; the sheet tracks your finger down and resists up. |

The logo is a train seen head-on with the crescent and star of the flag in its
windscreen. It is generated by `scripts/generate-assets.mjs` from the same
48-unit grid as the in-app `<LogoMark/>`, so the icon and the component cannot
drift apart.

Design decisions and their reasoning: [`docs/DESIGN.md`](docs/DESIGN.md).

## What it does

| | |
|---|---|
| **Explore** | Search pill, category rail, and a column of real photographs. No form on the home screen. |
| **Search** | Airbnb's three-card accordion, Where, When and Who, adapted for a journey, which needs an origin as well as a destination. |
| **Results** | List with a floating Map toggle and Airbnb-style price pins along the corridor. |
| **Train page** | Hero carousel, rating and reviews, operator, class picker, amenities, route map, calling points, sticky fare bar. |
| **Booking** | One page. Class, travellers with CNIC, payment method, price breakdown, one button. |
| **Ticket** | Perforated pass with a QR that regenerates every 45 seconds on the device, plus the PNR in full. |
| **Live journey** | Map with the train drawn nose-first along the alignment, platform panel, calling points with progress. |
| **Notifications** | Departure, an approach warning you choose the length of, arrival, and delay or platform changes for booked trains only. |
| **Stations** | Walking route and bearing, facilities, next departures, and onward transit: Metrobus, BRT, People's Bus, rickshaw, Careem. |
| **Offline** | Tickets and station data pinned and never evicted; writes queue and replay in order; the map falls back to bundled vector geometry. |

4,950 to 5,450) and `tests/fares.test.ts` holds the model to them.

## Google Maps

Split in two, because the halves have different security properties:

- **Rendering** uses the Maps SDK from the app with a *client* key. That key
  ships in the bundle by nature, so it is restricted by iOS bundle id, Android
  signing certificate and web referrer, with only the Maps SDKs enabled.
  `react-native-maps` on native, the Maps JavaScript API on web, each behind one
  `<Map/>` component.
- **Data**, meaning Directions, Geocoding, Places and Distance Matrix, goes through the
  gateway's `/v1/maps/*` proxy, which holds a *server* key. Those are billable
  and cannot be restricted by bundle id, so shipping one in an app binary means
  anyone who unzips the APK can spend your money.

With no key at all the app draws its bundled vector geometry instead. That is a
supported mode, not a degraded one: it is what runs in the Bolan tunnels.

```
EXPO_PUBLIC_GOOGLE_MAPS_API_KEY=...   # client key, app
GOOGLE_MAPS_SERVER_KEY=...            # server key, server/.env only
```

`npm run places` refreshes every station coordinate and Place ID from Google's
geocoder, rejecting any result that moves a station more than 2 km.

## Layout

```
app/                      Expo Router, one file per screen
  (tabs)/                 Explore · Wishlists · Trips · Inbox · Profile
  search.tsx              Where / When / Who
  results.tsx             list + map
  train/[id].tsx          the listing page
  book/[journeyId].tsx    confirm and pay
  ticket/[id].tsx         the gate screen
  journey/[serviceId].tsx live tracking
  station/[id].tsx        getting there, and getting onward

src/
  theme/                  tokens, type scale, provider
  components/
    brand/                the Safar mark
    primitives/           Text, Button, Touchable, Photo, Sheet, Heart…
    search/               search pill, category rail, calendar
    rail/                 train card, class picker, route timeline, QR ticket
    map/                  Map.native · Map.web · VectorMap fallback
  data/                   stations, trains, chainage, fares, geometry, photos
  services/               apiClient · offline · googleMaps · barcode · payments
  state/                  zustand stores
  utils/                  geo · time · format · polyline

server/                   the gateway (Node + Express + pg + ws)
scripts/                  asset, photo and geocode tooling
docs/                     architecture, security, offline, design, API
tests/                    40 unit tests, no test framework dependency
```

## Status

Verified: typecheck clean for app and gateway, 40 tests passing, and the web
bundle exports and renders every screen with no runtime errors in light and dark
mode.

Three integration points are deliberate, documented stubs that throw or return
empty rather than pretend:

- `server/src/security/tickets.ts`, `KmsSigner.sign`, against your KMS
- `server/src/routes/connections.ts`, `loadConnections`, against city transit feeds
- `src/services/payments.ts`, `openPaymentSheet`, against JazzCash, Easypaisa or a card PSP

The gateway is complete against the schema documented in
`server/src/db/legacyRail.ts` but has never been pointed at a real Pakistan
Railways database. That adapter is the first file to change.
